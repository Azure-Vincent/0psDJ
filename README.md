# Infrastructure Lab

An offline, interactive desktop application for learning how network services
work **internally** and how to **troubleshoot them from evidence**. It runs a
deterministic simulation of a small network (client, DNS server, router, Linux
server) in which every command, packet, log line and connection result is
computed from one consistent model, so breaking or fixing something has
coherent consequences everywhere.

> Design documents (architecture, curriculum map, UI layout, data model,
> troubleshooting-engine design, phased plan): [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)

## What is implemented

The foundation plus two complete lessons: **SSH** (Module B) and **Linux firewalls with nftables** (Module D), sharing one simulated lab and troubleshooting engine.

| Area | Implemented |
|---|---|
| **SSH lesson** (7 sections) | What it is · how it works internally (RFC 4251–4254, OS components, keys) · **interactive sequence diagram** generated by the engine (play/step/pause/reset, per-packet inspector with Ethernet/IP/TCP/UDP/ICMP/SSH fields, per-hop MAC rewrites, connection/session state) · **deployment guides** for Debian/Ubuntu, RHEL/Rocky and Windows Server with what/why/expected output, plus sandbox terminals · **configuration deep dive** with an `sshd -T` explorer running the real parser · troubleshooting method and error→layer map · **assessment** (ordering, multi-select, short answer, nft rules and sshd_config graded by the engine) |
| **nftables lesson** (7 sections) | Netfilter hooks, tables/chains/priorities, first-match rule evaluation, conntrack states, drop vs reject and the client symptom each produces, persistence (reload is atomic, restart flushes), iptables-nft/UFW/firewalld · hook diagram and **CIDR calculator** · **visualizer** of 7 traced runs (allowed, policy drop, reset, admin-prohibited, router forward drop, missing established rule, traceroute) where every hop names the exact deciding rule · deployment guides for Debian nftables, UFW, firewalld and Windows Defender Firewall · **packet tester** that evaluates any ruleset rule by rule · assessment (11 questions, firewall rules graded by the engine) |
| **Dependency map** | 12 dependencies of an SSH login; switch one off, predict the client message, then see the simulated output, server journal and trace |
| **Troubleshooting lab** | 19 tickets. Firewall set: stopped web server blamed on the firewall, leftover reject-with-reset, a /23 that blocks the office along with the guests, missing established rule (server cannot resolve names), router forward chain allowing only SSH; goals can be SSH logins, HTTP requests or name lookups, and unsafe fixes (policy accept, `udp sport 53 accept`, deleting the guest block) are rejected. SSH set: 14 tickets (beginner → advanced, including a two-fault ticket): sshd config errors, wrong port, firewall drop vs reject, stale DNS record, broken zone (SERVFAIL), missing return route, StrictModes permissions, client key permissions, host-key change, AllowUsers, KEX mismatch, missing authorized key, non-persistent firewall rule + disabled service. Terminals on ws01 and consoles on srv01/ns1/rtr01, notes, evidence log, diagnosis with misconception feedback, progressive hints, verification **now, after rebooting every host, and against security constraints**, root-cause analysis and reference repair after resolution |
| **Simulated shell** | `ip`, `ss`, `ping`, `traceroute` (UDP/TCP/ICMP), `dig`, `nslookup`, `host`, `getent`, `nc`, `curl`, `tcpdump`, `conntrack`, `nft`, `iptables` (iptables-nft view), `systemctl`, `journalctl`, `ssh` (-v, -p, -i, -o, interactive host-key and password prompts, remote commands), `ssh-keygen` (-lf, -R, -F), `ssh-keyscan`, `ssh-copy-id`, `sshd -t/-T [-C]`, `rndc`, `named-checkzone`, `sysctl`, `reboot`, `sudo`, file tools (`ls`, `cat`, `grep`, `sed -i`, `chmod`, `chown`, `stat`, `nano`/`vi` via an in-app editor …), pipes, redirection, `&&`/`||` |
| **Diagnostic commands** | Reference for 30 Windows and Linux commands (purpose, arguments, example output, interpretation, limitations) and practice: choose-the-command and spot-the-abnormality exercises |
| **Packet Lab** | 8 synthetic capture presets produced by the engine, Wireshark-style list/detail/hex views, display filters (`ip.addr`, `tcp.flags.syn`, `dns`, `icmp`, `&&`, `||`, `!` …), **PCAP export** (valid checksums; opens in Wireshark), explanation of what is and is not visible without keys |
| **Learning model** | Concept-level mastery (18 concepts) updated by answers, predictions and diagnoses; misconception tracking; prerequisite-aware review recommendations; troubleshooting history with every command run |
| **App** | Offline; Windows/Linux/macOS via Electron; light/dark/system theme; global search; glossary (50 terms); progress saved locally with export/import/reset |

## Requirements

- Node.js 20+ (tested with Node 22) and npm.
- Internet access only for `npm install` (it downloads dependencies and the Electron binary). The application itself needs no network.

## Install and run

```bash
npm install            # installs dependencies and the Electron runtime

npm run desktop        # build and launch the desktop app (Windows, Linux, macOS)
npm run dev            # or: development server at http://localhost:5173 in a browser
npm run desktop:dev    # Electron window pointing at the dev server (run `npm run dev` first)
```

`npm run build` produces the offline bundle in `dist/`. To ship installers,
add a packager such as `electron-builder` and point it at `electron/main.cjs`
and `dist/` (not included, to keep the dependency set minimal).

## Tests

```bash
npm test               # Vitest: 139 tests
npm run typecheck
```

The test suite covers the parsers (sshd_config first-match/Include/Match,
nftables, zone files, ifupdown), routing/TCP/ICMP behaviour (refused vs timed
out vs no route, retransmission timing, reboot semantics), the shell
(permissions, sudo, interactive prompts), every troubleshooting scenario
(**fault → expected symptom → reference fix → verification passes, including
after reboot**), security constraints rejecting bad fixes, all dependency-map
outcomes, assessment grading, PCAP checksums and display filters.

## Accuracy and sources

Behaviour follows RFC 4251–4254, 4253, 8308, 8709 (SSH), RFC 9293 (TCP), RFC 792
(ICMP), RFC 826 (ARP), RFC 1035 (DNS), and the behaviour of Debian 12 components
(OpenSSH 9.2p1, BIND 9.18, nftables 1.0.6, systemd 252). Where the simulation
simplifies (IPv4 only, synthetic cryptographic values, one TCP segment per SSH
message, tcpdump showing recent traffic rather than a live capture), the app
says so next to the feature. Reference links are listed in the SSH lesson.
